# 04: 修复失败与句组回退、单次请求与不重试

**Delivers:** P9, P10
**Blocked by:** 02 — 中文空缺触发、按 Translation Chunk 集中请求与只改中文的局部修复；03 — 句组内英文切分点移动与组内时间估算
**Status:** ready-for-agent

**Parent:** `.scratch/subtitle-local-alignment-repair/contract.md`

## What to build

把「可选优化不得破坏已经可用的翻译结果」落成可观察的失败语义：

- **整组回退**：可归属到某句组的无效候选，该组原英文、原中文、原时间码一起保留；同一请求中其他有效句组仍可正常采用。不逐行拼接新旧版本。
- **请求范围保留**：请求异常、空响应、或响应无法可靠归属到句组时，对受影响的请求范围保留原结果，不猜测对应关系、不混用新旧行。
- **不伪装**：原有输入不一致（例如字幕块数与中文行数不符）或输出写入失败，必须表现为真实失败，不能伪装成"修复已回退成功"。
- **请求经济学**：每个受影响 Translation Chunk 的一次生成执行至多请求一次修复；失败不自动重试，业务层与外部调用 adapter 都不追加修复尝试；修复不额外叠加超出现有配置的模型并发；正常翻译既有的重试语义不变。
- 可选修复失败不使原本能成功的 Job 失败：失败后仍使用原结果完成处理，生成原本的 Bilingual SRT。

## Acceptance criteria

- [ ] 注入一个结构可归属但非法的候选（例如改词、变块数或时间不合法）时，该句组输出的英文、中文、时间码与修复前逐块一致；同一请求内经校验有效的其他句组仍采用修复结果（C9.1）。
- [ ] 注入请求异常、空响应与无法可靠归属的响应时，受影响的请求范围保留原结果，产物中不出现新旧行混用或臆测的对应关系（C9.2）。
- [ ] 修复失败后原字幕输入未被破坏，最终仍生成与修复前一致的 Bilingual SRT，已有可用翻译不丢失（C9.3）。
- [ ] 在原字幕块数与中文行数不符、或最终产物写入失败的情形下，运行以真实失败结束，不被报告为"修复回退成功"（C9.4）。
- [ ] 一个 Translation Chunk 中存在多个待修复句组时，受控 adapter 记录到的修复请求恰好一次（C10.1）。
- [ ] 注入修复请求失败后，业务层与外部调用 adapter 均未追加任何修复尝试；正常翻译原有的重试语义与次数不变（C10.2、C10.3）。
- [ ] 修复不会使模型并发超出现有配置的翻译并发（C10.3）。
- [ ] 一次本应成功的翻译处理在修复调用失败时仍以成功结束，并产出可用的 Bilingual SRT（故事 23）。
