# 字幕中文空缺句组的局部对齐修复

Status: ready-for-agent

Contract: [已批准的 promises 与 seam 决策](contract.md)

## Problem Statement

用户通过 Bilingual SRT 对照英文语音与中文字幕学习。英文的一句话经常分布在多个带时间码的字幕块中，而中文翻译通常更短。当前翻译会整体理解句组，允许较少的中文行通过行号锚点落到对应英文字幕块，其余位置保留中文空白，避免后续句组整体错位。

这种回退保障了句组边界，却也接受了一些本可改善的结果：整句中文集中出现在第一个字幕块，后续字幕块只有英文，中文意义提前出现，影响同步对照。中文比英文短并不意味着不能切分；中英文非空行数相等也不意味着语义对应。

代表样例为用户提供的视频 How Games Use Feedback Loops 中的字幕编号 203–205（不是文件物理第 203 行）：

- 203：This is one reason why it was so important for Capcom to never
- 204：reveal that Resident Evil 4 was
- 205：using a dynamic difficulty system.

当前整句中文“这就是为什么卡普空绝口不提《生化危机4》使用了动态难度系统的原因之一。”集中在 203，204、205 没有中文。它可以作为局部修复的代表案例；英文切分也可以考虑将 never 移到下一块，与 reveal 连在一起。

## Solution

在后续 Job 的正常翻译之后、最终生成 Bilingual SRT 之前，对存在中文空白的句组按需增加一次局部对齐修复。

只发送需要修复的完整句组及已有中文，而不是整篇字幕，也不是只发送没有中文的英文字幕块。优先改写和重新切分中文，使其意义尽量按英文出现顺序展示。用户接受未完的短语和英文语感的“翻译腔”，不要求每块中文独立成句，但不得丢失或增加信息。

如果英文原切分明显割裂短语，可以在句组内调整英文切分点。英文来自实际语音，只能移动切分点，不能改写内容、增删单词或改变顺序。保持字幕块数量不变；英文切分变化时，由程序基于修复前的原始字符位置与时间码估算组内新时间边界，整组起止时间保持不变。

允许部分改善，仍然可以存在中文空白。修复失败或结果不合法时，整个句组保留原英文、原中文和原时间码，不让可选优化破坏已经可用的翻译结果。不提供已有 Bilingual SRT 的独立修复入口。

## User Stories

1. As an 英文视频学习者, I want 中文字幕尽量在对应英文意义出现时显示, so that 我可以同步对照两种语言而不提前读完整句翻译。
2. As an 英文视频学习者, I want 已合并的中文在可行时重新切分到多个字幕块, so that 更短的中文不会不必要地集中在一个时间片中。
3. As an 英文视频学习者, I want 修复优先保留英文字幕的现有切分, so that 原本可用的英文展示不会为适配中文而被随意调整。
4. As an 英文视频学习者, I want 中文可以调整措辞和语序以跟随英文, so that 对照准确性优先于地道的中文表达。
5. As an 英文视频学习者, I want 中文可以停在未完的短语上, so that 一个英文句子分成多个字幕块时仍能逐块对照。
6. As an 英文视频学习者, I want 重新切分不拆开中文词语和专有名词来硬凑行数, so that 字幕仍然可以阅读。
7. As an 英文视频学习者, I want 修复保留整句中文的完整意思和术语, so that 对齐改善不会引入遗漏、重复或新增事实。
8. As an 英文视频学习者, I want 明显割裂英文短语的切分点可以局部移动, so that never reveal 之类的表达可以更合理地显示。
9. As an 英文视频学习者, I want 英文单词、顺序和标点保持原样, so that 英文字幕仍然对应原本语音，而不是被重新改写的句子。
10. As an 英文视频学习者, I want 修复保持原有字幕块数量, so that 局部对齐不会演变为整条字幕的重新分段。
11. As an 英文视频学习者, I want 修复不跨句组移动内容, so that 当前避免后续句组错位的保障继续成立。
12. As an 英文视频学习者, I want 只改中文时保持所有时间码不变, so that 不需要调整的英文同步效果不被影响。
13. As an 英文视频学习者, I want 英文切分变化时相应估算组内时间边界, so that 被移动的英文不只是机械地沿用原字幕块的显示时间。
14. As an 英文视频学习者, I want 局部调整保持整组起止时间及组外字幕不变, so that 修复不会使相邻句组发生时间漂移。
15. As an 英文视频学习者, I want 在只能改善部分对应关系时也保留改善, so that 无须为追求每行都有中文而放弃有效修复。
16. As an 英文视频学习者, I want 无法合理切分的内容仍然允许合并中文和中文空白, so that 系统不会为了消灭空行而产生生硬碎片或错误翻译。
17. As an Job 发起者, I want 只有存在中文空白的句组才触发额外修复, so that 普通翻译不会无条件增加调用成本和等待。
18. As an Job 发起者, I want 修复请求包含完整问题句组及其已有中文, so that 模型能够重新分配已合并的意思，而不是对空白位置重复翻译。
19. As an Job 发起者, I want 同一 Translation Chunk 内的待修复句组集中提交, so that 不必为每一个空白字幕块分别调用模型。
20. As an Job 发起者, I want 不发送整篇字幕重新翻译, so that 局部问题只产生局部处理成本。
21. As an Job 发起者, I want 没有中文空缺的句组不被这个修复步骤修改, so that 现有正常输出保持稳定。
22. As an Job 发起者, I want 非法修复结果按整个句组回退, so that 新旧英文、中文和时间码不会混合造成重复或遗漏。
23. As an Job 发起者, I want 额外修复请求失败时仍保留已经成功的翻译, so that 可选优化失败不会使原本可完成的 Job 失败。
24. As an Job 发起者, I want 局部修复不会无限重试, so that 优化失败时可以及时使用现有回退体验完成处理。
25. As an Job 发起者, I want 后续正常翻译生成的 Bilingual SRT 自动包含可用的局部改善, so that 我不需要再手工搬移中英文字幕。
26. As an 已有字幕的使用者, I want 本次功能不主动重写已有字幕文件, so that 已经生成的产物不会受到未经请求的批量修改。

## Implementation Decisions

### 领域和行为范围

- 沿用项目的 Job、Stage、Progress、Translation Chunk、Workspace 和 Bilingual SRT 术语。
- 本功能属于现有翻译处理中的局部优化，位于正常翻译获得可用结果之后、最终 Bilingual SRT 生成之前。不新增用户可见 Stage，也不重新定义 Job Status 或 Progress。
- 本文的“句组”沿用现有按英文句末标点形成的整体翻译单位；“字幕块”指一个带编号、起止时间和文本的 SRT 条目，不是条目内部的视觉换行。
- 触发条件为句组中至少存在一个有英文但中文为空的字幕块。中文空白是触发信号，不是修复失败或翻译缺失的充分证据。
- 不因中英文非空行数相等而额外启动语义检查；该类问题不属于本次范围。

### 请求范围与处理优先级

- 使用已有译文进行局部修复，不重新翻译整篇字幕。
- 每个 Translation Chunk 中待修复的完整句组集中进行一次额外请求；每组必须包含全部英文字幕块和已有中文，包括承载合并译文的非空位置。
- 未触发修复的句组不发送给此次修复调用，也不修改。
- 同一次局部修复先考虑只改中文；仅在英文切分明显割裂表达、确有助于对齐时，才调整英文切分点。这个优先级不要求再增加一次单独调用。
- 中文允许局部改写和调整语序，允许翻译腔和未完短语；完整语义与术语应保留，不能为填满空白增加、重复或遗漏信息。
- 不按字符数平均切中文，不要求中文非空行数等于英文行数，不将空白数量减少作为语义质量的充分证明。
- 保持字幕块数量及句组边界不变，不产生空英文字幕块；允许有效修复后仍有部分中文空白。

### 英文内容与时间约束

- 英文只允许移动切分点，不允许修改单词、顺序和标点。比较时可以忽略字幕块分隔造成的空白差异，但不能以空白归一化掩盖英文内容变化。
- 时间码由程序计算，不接受模型自由生成的时间码。
- 英文切分没有变化时，时间码必须保持原样，即使中文发生改写或重分配。
- 英文切分变化时，基于修复前的英文位置和时间码，沿用现有按字符位置估算时间的思路，调整组内相关时间边界。
- 保持整组起止时间和组外字幕不变；调整后的时间应有序、不因修复引入块间重叠，且每块持续时间为正。无法满足合法时间约束的候选不可采用。
- 时间估算不是词级音频对齐。不能声称新边界等于单词真实发音时间，也不能在重复估算的结果上累积漂移。

### 接受与回退

- 字幕块数量、英文内容保全、句组范围和时间合法性由程序做确定性校验；语义保全和语义对应不能仅由这些结构校验保证。
- 接受合理的部分改善，不以所有中文空白都消失为前提；无法合理改善时允许明确保留原结果。
- 回退的单位是整个句组：原英文、原中文、原时间码一起保留，不能逐行拼接新旧版本。
- 对能够可靠归属到句组的无效候选按句组回退；请求失败或响应无法可靠归属时，对受影响的请求范围保留原结果，不猜测对应关系。
- 局部修复不循环重译。额外调用失败时直接使用原结果；现有正常翻译的重试及失败语义保持不变。
- 下游生成 Bilingual SRT 必须使用同一已接受结果中的英文、中文和时间码，避免只应用文字修改却遗漏相关时间调整。

### 架构决策的边界

- 已有标点处理并行和失败即停的架构决策针对标点处理，不在本功能中修改；本功能的回退仅适用于正常翻译成功之后的可选局部修复。
- 未决定新模块划分、接口形状、响应 schema、Workspace 中间产物格式或 seam 放置。以上由 /to-contract 基于现有实现选择，不在本规格中预设。

## Testing Decisions

- 现有翻译对齐回归测试以临时目录和替代模型响应运行翻译行为，已有“较短中文句组保留空白且不把下一句译文挪上来”的先例，以及末尾空白行往返读写的覆盖。实现时应保留这些行为保障，不将其改为强制每块都有中文。
- 验证应观察修复后的字幕内容、对应关系、时间与回退结果，不通过精确钉死提示词措辞、内部调用转发或字段复制来证明正确性。
- 确定性结构错误和失败回退应使用可控模型响应复现；最终保留哪些测试以及每项承诺的覆盖，留给 /to-contract 决定。
- 用户提供的 203–205 是代表性评估样例，应观察完整句组是否得到合理修复。将 never 移到下一块是允许的候选，不是模型必须逐字输出的唯一答案。
- 需要区分结构校验与翻译质量评估：模拟响应通过不能证明真实模型一定能正确切分；不能把中文空白变少作为唯一质量证据。
- 已讨论的验证场景包括：只改中文且英文及时间不变；英文合法移动切分并调整组内时间；部分改善但保留空白；英文被改写、块数变化、时间不合法或额外调用失败时完整回退；未触发的句组不发生额外修复。
- 本规格不决定测试 seam、接口承诺分配或各项承诺的测试覆盖矩阵，也不要求在编写规格时执行功能测试。

## Out of Scope

- 对已有 Bilingual SRT 提供独立修复命令、界面或批处理入口，以及主动重写已有字幕产物。
- 重新发送整篇字幕进行翻译，或无条件复查全部句组。
- 修复没有中文空白、但语义落位不正确的其他情况。
- 修改英文措辞、语法、单词、标点或语序，包括借机纠正英文识别错误。
- 改变字幕块数量、跨句组移动文本、重新制作整条字幕时间轴，或更改现有句组划分规则。
- 强制每块都有中文，以字数均分、拆词或补充无依据内容凑齐行数。
- 引入语音识别、词级音频强制对齐或由模型猜测时间码。
- 改动标点处理的并行及失败策略、正常翻译的重试语义，或新增用户配置和可见流水线 Stage。
- 无限修复循环，以及为本次功能引入无关的遥测、监控或架构重构。

## Further Notes

- 该规格来自本轮已确认的 Q1–Q9 取舍：中文可改写、按英文语序对照优先、按需调用；英文只改切分；采用字符位置近似调时；优先只改中文；保持块数；接受部分改善；仅接入后续翻译流程。
- 对齐目标是“对应意义尽量在对应英文时间片出现”，不是中文地道程度，也不是非空行数指标。
- 当前提示已经要求尽量逐行对应，但结构合法的合并译文会被直接接受。因此本功能需要显式局部修复与结果回退，不能只重复一句提示词要求就视为交付。
