# iOS Safari 长按临时倍速

Status: ready-for-agent

Contract: [长按临时倍速契约](contract.md)（approved，已批准）

## Problem Statement

用户在 iOS 手机上的 Safari 中串流观看 Video，使用页面自制的横屏全屏，而不是 iOS 系统原生全屏。观看过程中，用户希望暂时加速略过熟悉或节奏较慢的内容，但不想反复打开倍速菜单，也不希望改变原本的播放速度偏好。

当前播放器使用浏览器原生视频控件，已有播放位置记忆和自制横屏全屏功能，但没有长按临时倍速交互。

## Solution

在普通页面播放和自制横屏全屏中，用户可以在视频画面的非控件区域按住 500 毫秒，临时以固定 2× 播放；松开后立即恢复长按前的速度。

仅在视频正在播放时生效，暂停时长按不启动播放。明显滑动或手势中断会结束本次操作并恢复原速，避免意外持续加速。整个操作不显示提示，不影响原有控件和短按操作。

## User Stories

1. As an iOS Safari 观看者, I want a 在串流观看 Video 时长按临时倍速的操作, so that 我不必反复打开倍速菜单就能暂时加快观看节奏。
2. As an iOS Safari 观看者, I want a 普通页面播放时可用的长按操作, so that 我不必先进入全屏才能临时加速。
3. As an iOS Safari 观看者, I want a 自制横屏全屏中可用的长按操作, so that 我能保持习惯的全屏观看方式。
4. As an iOS Safari 观看者, I want a 覆盖视频画面非控件区域的触发区域, so that 我无需寻找特定侧边或小按钮。
5. As an iOS Safari 观看者, I want a 按住 500 毫秒才触发的门槛, so that 普通短按不会误触加速。
6. As an iOS Safari 观看者, I want a 固定切到 2× 的临时速度, so that 加速效果不会随着当前速度成倍变化。
7. As an iOS Safari 观看者, I want a 持续按住期间维持临时倍速的操作, so that 我能用按住的时间控制加速持续多久。
8. As an iOS Safari 观看者, I want a 松手立即恢复长按前速度的行为, so that 临时加速不会改变后续观看节奏。
9. As an 原本以 1.5× 播放的观看者, I want a 长按变为 2×、松手回到 1.5× 的行为, so that 我的原有速度不会被重置成 1×。
10. As an 暂停观看的用户, I want a 暂停时不会启动播放的长按行为, so that 接触屏幕不会意外恢复播放。
11. As an iOS Safari 观看者, I want a 容忍轻微手抖的长按操作, so that 我不需要完全静止手指才能保持加速。
12. As an iOS Safari 观看者, I want a 明显滑动时取消尚未触发的长按行为, so that 滑动不会在稍后意外触发加速。
13. As an iOS Safari 观看者, I want a 加速期间明显滑动就恢复原速的行为, so that 我能自然地终止本次操作。
14. As an iOS Safari 观看者, I want a 切到后台时结束临时倍速的行为, so that 返回页面后不会遗留意外的加速状态。
15. As an iOS Safari 观看者, I want a 切换自制全屏时结束当前长按的行为, so that 画面模式变化不会留下未结束的手势。
16. As an iOS Safari 观看者, I want a 系统取消手势时恢复原速的行为, so that 即使没有正常收到松手，视频也不会一直保持临时倍速。
17. As an iOS Safari 观看者, I want a 中断后必须重新按住 500 毫秒才加速的规则, so that 已取消的手势不会自行恢复。
18. As an iOS Safari 观看者, I want a 不显示倍速提示的交互, so that 视频画面不被额外文字或浮层打扰。
19. As an iOS Safari 观看者, I want a 不受长按干扰的播放按钮和进度条, so that 我仍可正常暂停、播放和定位视频。
20. As an iOS Safari 观看者, I want a 不受长按干扰的自制全屏按钮, so that 我仍可正常进入和退出横屏全屏。
21. As an iOS Safari 观看者, I want a 保持原有短按行为且长按结束不误触播放或暂停的交互, so that 临时倍速不会打断播放。

## Implementation Decisions

以下记录本次对话已经明确的产品行为及当前实现事实，不决定模块拆分、接口边界或测试接缝。

- 领域术语采用“长按临时倍速”：正在播放时按住画面临时以固定 2× 播放，松开恢复长按前速度；暂停时不启动播放。
- 目标环境是 iOS Safari；支持普通页面播放和页面自制横屏全屏。用户明确只使用自制全屏，不使用系统原生全屏。
- 当前播放器基于浏览器原生视频控件，并有独立的自制横屏全屏入口。保留原有控件操作和短按行为。
- 可触发区域为视频画面的非控件区域，不限定左侧或右侧；播放、进度条、进入及退出全屏等控件不应触发本功能。
- 持续按住 500 毫秒才开始临时倍速，未达到门槛就松手不得触发。
- 临时播放速度为绝对值 2×，不是当前速度乘以二。结束后恢复长按前的实际速度，而不是统一恢复为 1×。
- 仅在正在播放时生效，不因暂停状态下的长按自动启动播放。
- 明显滑动定义为相对最初按下位置的位移超过 12 CSS 像素；轻微移动不取消。此规则同时适用于等待触发期间和已经加速期间。
- 明显滑动、松手、切到后台、切换全屏或系统取消手势，均结束本次手势。尚未触发时取消等待；已经触发时恢复原速。
- 手势结束或中断后，不沿用旧的按住时长；再次加速需重新按下并持续 500 毫秒。
- 不显示文字、图标或浮层形式的倍速提示。
- 长按结束不应产生额外的播放或暂停误操作。
- 本次对话没有选定实现接缝、模块接口或状态管理结构。这些留给 `/to-contract`，不在此规格中预先决定。

## Testing Decisions

- 本次对话没有选定测试框架、已有测试范例、替身或自动化测试层级；不将尚未核实的测试设施作为既定事实。
- 行为验证应覆盖目标使用环境 iOS Safari，以及普通页面与自制横屏全屏两种观看模式。桌面浏览器验证不能单独作为 iOS Safari 触摸兼容性的结论。
- 如果实现环境无法直接验证真实 iOS Safari，应明确记录该限制和已实际验证的范围，不宣称完成了真机验证。
- 等待门槛、恢复原速、滑动与中断取消、暂停状态、原生控件及短按不受干扰，都是需要验证的用户可观察行为；具体在哪些接缝验证、采用什么工具以及覆盖如何分配，留给 `/to-contract`。
- 本次仅发布规格，不修改播放器行为，也不将文档发布视为功能测试通过。

## Out of Scope

- iOS 系统原生全屏播放器中的长按倍速支持。
- 为 Android、桌面鼠标或其他浏览器新增专门交互或兼容性承诺。
- 可配置的长按时长、滑动阈值或临时倍速。
- 三倍速、当前速度乘以二、点按锁定倍速等其他加速模式。
- 倍速提示、动画提示或额外的控制面板。
- 暂停时通过长按启动播放。
- 重做整套播放器控件或改变既有播放位置记忆行为。
- 改动 Video 下载、字幕处理、Job 流水线或服务端串流处理以实现新需求。
- 在本规格阶段决定模块接缝、接口契约、实现任务拆分或编写播放器代码。
