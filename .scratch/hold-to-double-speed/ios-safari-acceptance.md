## 2. 准备步骤（电脑侧 + 手机侧）

### 2.1 启动服务（电脑侧）

1. 前置：Python 3.8+、`PATH` 上有 ffmpeg、有可用的 NVIDIA GPU（实时转码用 NVENC）。本机已复核：ffmpeg N-123918、NVIDIA RTX 4070 SUPER。
2. 在仓库根目录任选一种：
   - `python server.py`（默认用 `config.json` 里的 `video_dir`，本机为 `E:/Developer/youtube-playground/new-streaaming`）
   - `python server.py "D:\某个视频目录"`（临时指定目录）
   - 双击 `start-all.bat`（同时再开一个 worker 窗口，做下载/字幕流水线；只做本次验收用不到）
3. 终端会打印：
   - `Streaming server: http://<局域网IP>:8888/`，以及一个二维码；
   - 若 mDNS 可用，还会打印 `http://my-streaming.local:8888/`。**本机实测 mDNS 不可用**，请以 IP 地址为准。
4. 本次实测（2026-09-20，仅验证准备步骤可行）：`python server.py` 打印 `Streaming server: http://192.168.5.4:8888/`、找到 43 个视频；索引页与 `/play/<id>` 页面正常；`playlist.m3u8` 为 VOD；`segment_0.ts` 能正常取到（约 2.4 MB）。你机器上的 IP 可能不同，**以终端打印的为准**。
5. 排障：端口固定 `8888`，若提示地址被占用，先关掉上一次的服务器窗口；Windows 防火墙弹窗时允许 Python 在「专用网络」上通信（否则手机连不上）。

### 2.2 手机侧打开页面

1. iPhone 与电脑连**同一个 Wi-Fi**（别用访客网络或开了 AP 隔离的网络）。
2. 用 iOS **Safari** 打开 `http://<局域网IP>:8888/`（也可用相机扫终端里的二维码）。
3. 页面标题 `My Streaming`；向下滚动到「视频」列表，点一个视频名进入播放页（链接形如 `/play/<id>`）。列表里带 `CC` 标记的表示有字幕。
4. 若打不开：核对 IP 与端口是否与终端一致、手机与电脑是否同网段、防火墙是否放行、`8888` 是否被别的程序占用。

### 2.3 选视频并确认「真的在播放」

1. 必须用**实际串流视频**（`config.json` 的 `video_dir` 里的 mp4）。**不要**用 `tests/` 下的合成夹具视频——那属于测试范围，不代表真实码率与转码路径。
2. 选一个时长适中、画面持续运动、有连续对话或明显节奏的视频，便于听出/看出快慢差别。
3. 首次进入某个视频会触发实时转码：如果一直转圈，先等几秒到几十秒（分段还没生成时服务端会最多阻塞 60 秒等文件出现），不要把它当成倍速问题。
4. 判定「真的在播放」：画面在动、原生控件条上的时间计数在走、拖进度条能跳转。
5. **只有在确认真的在播放、画面流畅不卡顿的那一刻才做验收行**。若出现转圈/卡顿，先把该行记为 `未执行`，处理后重做；转码或网络问题不是本功能的行为。
6. 若画面一直不出来：看服务器窗口与 `temp/<video_id>/ffmpeg.log` 的报错——那是转码/环境问题，与长按倍速无关。

### 2.4 认识两种观看模式

| 模式 | 怎么进 | 怎么退 | 里边的控件 |
|---|---|---|---|
| 普通页面 | 进入 `/play/<id>` 的默认状态：顶栏有「← Back」，画面占满中部，**右下角（原生控件条上方）有一个方形全屏图标** | —— | iOS 原生控件条在画面底部，轻点画面即可唤出 |
| 自制横屏全屏 | 点右下角那个方形图标。画面淡出淡入一下并**旋转 90°**，顶栏消失，「×」退出按钮出现在屏幕一角（进入后可见） | 点屏幕上的「×」；或当系统触发了旋转时把手机转回竖屏，页面会自行退出该模式 | 原生控件的播放/暂停与进度条**跟着画面一起旋转**，贴合画面下边 |

- 本清单里的**「非控件区域」**＝画面上除原生控件条、方形全屏图标、「×」以外的区域。建议按在**画面竖直方向约 1/3 高度处**（自动化用的按压点就在那里），这样不会碰到通栏控件。
- 本模式的旋转是页面自己做的（把播放器容器转 90°）。进入后请按你平时看这个模式的方式把手机摆正即可；**本清单不要求你关心几何实现**，只要求在该模式里能正常观看与操作。

### 2.5 建立手感与感知基线（几分钟，一次做完）

1. **一秒的节奏**：用秒表 App 熟悉「一秒」。`明显长按` = 心里数「一」再多停一小会儿（约一秒或更久）；`明显短按` = 快速点一下（明显短于门槛；默认 500 毫秒即明显短于半秒，配置成 350 毫秒时要更快）。
2. **一指宽的滑动**：手指在屏幕上移动大约一个指腹宽（约 1 厘米以上）算「明显滑动」；几乎不动或只有轻微手抖算「没有滑动」。
3. **速度三档校准**：用原生控件把速度依次设成 1×、1.5×、2× 各看几秒，记住三档的快慢差别。后面所有「明显加速 / 恢复原速」都按这个校准判断。
4. **原生结果基线**：在非控件区域轻点一次，记下发生了什么（票 01/02 实测的桌面基线是「webkit 的真实 tap 点画面会切换播放/暂停，chromium 的触摸 tap 不会」）。把本机结果填到 P10-1 行——它是 P10 的对照基线。
5. 若你设备上的原生倍速按钮会显示当前档位，就用它读「现在是几档」；若它不随页面变化更新，就只按第 3 步校准出来的感觉判断。

### 2.6 怎么把原生速度设成 1.5×（P2 需要 1.5× 起步）

1. 轻点画面唤出原生控件条 → 找到显示当前倍速的按钮（iOS 16 及以上一般显示成「1x」）→ 选 `1.5×`。
2. 确认改成功：画面节奏比 1× 快一截（用 §2.5 第 3 步的校准判断）。
3. 若你的 iOS 版本的 Safari 控件里**找不到倍速入口**：把 P2 里 1.5× 起步的行记为 `未执行` 并注明原因。1.5×→2×→1.5× 的规则已由自动化证明，真机上这部分就只能算未覆盖，**不得标为通过**。
4. 自制横屏全屏里要 1.5× 起步：进入全屏前先设好 1.5×（同一段播放不会因为进入模式而重置）。
