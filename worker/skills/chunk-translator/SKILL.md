# Chunk Translator

将英文纯文本字幕块翻译为中文，采用「按句组整体翻译」，确保翻译流畅自然且按句组对齐，允许中文行数少于英文。

## 使用场景

用户有一个从 SRT 字幕提取出的英文纯文本文件（每行一句/一段，无时间码和序号），需要将其翻译为中文，输出为一个按句组对齐、允许中文行数少于英文的纯中文文本文件。该中文文件将作为中间产物，后续被合并回字幕格式用于中英对照学习。

## 核心原则

### 为什么按句组翻译而不是逐行翻译？

字幕文本由口语碎片组成，逐行翻译会丢失上下文导致译文生硬、不连贯。英文字幕常把同一句话拆成多个 SRT 块，所以先把这些块组成**句组**，把每个句组作为一个整体翻译，能理解语境、产出自然中文。

### 为什么允许中文行数少于英文？

中文比英文更紧凑，一个 3 行的英文句组往往只需 2 行甚至 1 行中文。此时最重要的是**保持句组边界**：中文宁可少写几行，也不能借用下一句的译文来凑行数。缺失的行会在最终合并时显示为空白行，避免下一句被挤上来。

### 为什么用意译而非直译？

英文口语中常有口误、不完整句、重复表达（如 "And by the way, in g by game I mean..."），直译会让中文也充满语病。意译在保持原意的前提下，用自然中文口语重新表达，更适合作为学习对照材料。

## 执行流程

### 第1步：读取与分组

1. 读取英文输入文件，识别每个**句组**
2. 句组以句子结束符（`.` `!` `?` `…`）为边界；同一句被拆成多行时，这些行属于同一个句组
3. 记录句组数量 G，以及每个句组内的英文行数

### 第2步：按句组整体翻译

将每个句组整体翻译为流畅中文，遵循以下翻译原则：

- **意译优先**：用自然中文口语表达，不拘泥于字面翻译
- **修正口误**：英文原文的口误、重复、不完整表达，在中文里自然修正——不要说"我的意思是说，我是说RPG"，而是直接说"我指的是RPG"
- **保持语气**：保留原文的疑问、感叹、迟疑、反问等语气特征
- **术语一致**：RPG、类型等专有术语保持翻译一致性，不要一会翻译为"角色扮演游戏"一会简称"RPG"，统一使用
- **风格**：口播视频风格，亲切自然的中文口语，像是中国UP主在说话

### 第3步：按句组输出中文

输出时保持 G 个中文组，组与组之间用空行分隔：

1. 每个中文组对应一个英文句组
2. 中文组内可以只有 1 行，也可以有多行，**不强制等于英文行数**
3. 如果中文比英文短，宁可少写几行，也绝不要从下一组借用内容
4. 组顺序必须与英文句组一致，不得合并、拆分或跳过任何组

**重要提醒**：

- 英文句组里多行只是同一句话的时间轴切分，不是独立句子
- 中文组内部可以按自然断句分行，不必对应英文每一行
- 中文少写造成的空缺最终会变成空白行，这是允许且预期的

### 第4步：校验与输出

1. 数一遍中文组数量，确认严格等于 G
2. 检查每个中文组内至少 1 行、没有跨组内容
3. 输出文件为纯文本；可按组用空行分隔，便于后续按句组合并
4. 不输出英文原文、序号、组号或任何解释

## 输出格式示例

输入文件 (`sample.txt`，5行英文，3个句组)：
```
Hi everyone, it's me Tim.
Today I want to ask you a question.
Would you play a game that?
What I mean by this is I'm going to describe several
game ideas and I'm curious if you would play that game.
```

输出文件 (`sample_chinese.txt`，3个中文组，组间空行)：
```
大家好，我是Tim。
今天我想问你们一个问题。

你会玩这样的游戏吗？

我想说的是，我会描述几个游戏创意，
很好奇你们会不会玩那个游戏。
```

## 关键约束

- **按句组翻译**：不要把同一个英文句组拆开逐行独立翻译
- **组数必须严格相等**：输出中文组数量 == 输入英文句组数量，这是最高优先级
- **组内行数允许减少**：中文比英文短时不要用下一句凑行，缺失行会放在该句组靠前位置，中文行尽量靠后对齐
- **语义对应优先于断句自然**：组内断句不自然可以接受，但跨组错位不可接受
- **纯文本输出**：不在输出文件添加序号、"第X行："等标记
- **禁止修改原文件**：只创建新的中文文件
