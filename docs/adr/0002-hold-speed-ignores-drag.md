# 长按临时倍速：位移不结束手势，只有松手或中断才恢复原速

原先的实现把手势期间「手指相对按下点滑动超过 12 CSS 像素」当作结束条件（等待期取消等待、加速期恢复原速）。
2026-09-20 用户在实际使用后决定反转：手势一旦在画面非控件区域开始，位移就完全不参与判定——等待期滑出多远
都照常满门槛触发固定 2×，加速期滑出多远都保持 2×；结束只有两条路：松手，或中断（切到后台、进入或退出
自制全屏、系统取消触摸、第二根手指落下）。理由是按住期间的滑动大多是无意的抖动或换握姿势，按位移取消
会让「按住加速跳过一段内容」这个主要用法频繁掉速。

## 考虑过的替代方案

- 保留原规则，只把容差从 12 像素放大：仍有「滑到某个距离就掉速」的问题，只是把边界推远。
- 按住期间用 `touch-action: none` / `touchmove` + `preventDefault()` 压制浏览器接管手势：本仓库此前
  在 iOS 上试过 `touchstart` + `preventDefault`，因页面渲染异常未取得可信结论、改动已全部回滚
  （见 `.scratch/hold-to-double-speed/ios-safari-acceptance.md` 的已知平台限制），本次不重复该路线。
- 给按住时长加上限兜底：与「按住多久就加速多久」冲突，且会打断按着跳过一整段内容的真实用法，不做。

## 影响与已知限制

- 实现是纯删除：`server/static/player.js` 去掉 `touchmove` 监听、`HOLD_SLOP_PX` 常量与按下点坐标，
  `holdBegin` 只记录按下瞬间的速度与是否在播放；结束仍只有 `holdEnd()` 一个出口。
- 达标前抬手仍然结束手势，所以「快速滑一下」永远不会误触发；慢慢滑着按住不动，到门槛必然进 2×。
- 播放器页面不可滚动（`player.css` 把 `html, body` 固定为 100% + `overflow: hidden`，viewport 也限制
  缩放），所以「滑动被浏览器当成页面滚动而抢走触摸」这条路径基本不存在；剩下的真机风险是长按放大镜
  （loupe）或选择手势导致系统改发 `touchcancel`——那会按「中断」结束手势。桌面自动化答不了这一条，
  需真机复验。
- 这不是对原契约的修订，而是新需求：`.scratch/hold-to-double-speed/` 里 P4/P5 的滑动行与真机记录
  描述的是旧行为，已被本决定取代，保留为旧版本的历史记录。
